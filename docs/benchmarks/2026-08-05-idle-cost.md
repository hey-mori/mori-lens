# What Lens costs while you are not using it

**2026-08-05**, Windows 11 build 26200, release build, measured with
`Get-Process` over 30 seconds with the pointer untouched.

## Why this was run

Every other number in this repository is about a hover: how fast text is
acquired, how long a translation takes, how quickly a card appears. None
of them describe the other 23 hours.

A tray tool is judged on that. One that costs a visible slice of a core
while doing nothing gets uninstalled from a laptop no matter how good it
is when it works.

## Before

```
CPU over 30s idle: 469 ms  (1.56 percent of one core)
working set: 15.7 MB
```

The pointer loop samples every 25ms, and on each sample it asked which
process owns the window under the pointer. That answer decides whether
the policy permits a read at all, so it cannot be skipped.

Getting it opened a process handle and queried its image path, **forty
times a second**, to be told the same thing every time.

## After

```
CPU over 30s idle: 47 ms  (0.16 percent of one core)
working set: 15.8 MB
```

Ten times less, for the same behaviour.

## What changed

The answer is cached, keyed on the **process id**, not the window handle.

That distinction is the whole reason this is a cache rather than a
gamble. A process's executable cannot change while it runs, so a hit is
not merely probably right, it is right. Window handles are recycled: a
stale name on a reused handle could hand a password manager the tier that
belonged to a browser, and this lookup is what the deny list is applied
to.

Getting the process id is a lookup in the window manager and opens
nothing, so it is still done on every sample. Only the expensive half is
skipped.

Measured per call, over ten thousand samples, which is four minutes of
hovering at the loop's rate:

```
10000 samples · 4.0us each · 0 wrong
```

## And once more, after adding a watcher

Live settings reload and dark-mode following need something looked at on
a timer. Naively, once a second for both:

```
idle CPU: 94 ms over 30s (0.31 percent of one core)
```

**The watcher doubled the idle cost on its own.** Not the file: a stat is
one syscall. Reading the system's appearance opens four registry values,
and it was being asked once a second for an answer that changes about
twice a year.

Split, so the file is checked every second and the appearance every five:

```
idle CPU: 47 ms over 30s (0.16 percent of one core)
```

Back to the number before the feature existed. Taking up to five seconds
to notice dark mode is not a delay anyone will attribute to Lens.

## What this does not establish

Idle with the pointer parked over one window, which is the common case
and the easy one. A pointer sweeping between many windows pays a lookup
per new process, and nothing here measures how often that happens in real
use.

Memory was never the problem and is unchanged.

## And what it costs while you *are* using it, 2026-08-06

Everything above is a Lens that captures nothing. `ocr = automatic` makes
a hover the accessibility path could not serve fall through to pixels, and
in VS Code that path fails at 96% of sampled points, so in an editor
nearly every settled hover captures the screen and recognises it.

Twenty fall-throughs, one every 500ms, which is brisk reading against a
320ms dwell rather than a stress test. Process CPU time, kernel and user,
because a battery does not care about the 60ms a fall-through spends
asleep waiting for the compositor.

```
wall clock   10.0s
CPU used     3578 ms
per reading  179 ms of CPU
             35.7 percent of one core, sustained, while somebody reads
```

**Against 0.16 percent idle.** Two hundred and twenty times, and that is
after the crop that took a fall-through over a margin from 887ms to 331ms
of wall clock.

## What was done about it

Nothing, and that is the decision.

A minimum interval between automatic captures would bound this, and it
would do it by refusing to read at moments a reader was asking to be read
to. A feature somebody turned on should not quietly become a slower
version of itself; the cost belongs in front of them instead. So the
number is in the settings file beside the option, in `--help`, in the
banner when the mode is on, and in the privacy model.

`manual` is unchanged and remains the default: `Ctrl+Alt+O` pays this
once, when somebody asked for it.
